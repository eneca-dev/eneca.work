# Пользователи: кадровые периоды и текущий состав

При включённой кадровой истории «Завершить работу» закрывает период сотрудника, сохраняя профиль и загрузки. Последний рабочий день включён; с наступлением следующего дня Минска сотрудник скрывается из текущего списка пользователей и строк текущего таймлайна «Отделы».

В списке пользователей переключатель «Показывать завершивших работу» возвращает завершивших работу. В «Отделах» переключатель «Показывать историю состава» возвращает также прежние строки переведённых сотрудников: по умолчанию сотрудник показан только в текущих отделе и команде. Гостевые строки по выданным грантам сохраняются. Полностью прошлый диапазон «Отделов» автоматически показывает исторический состав. Фильтрация меняет только отображаемые строки: исходные query-снимки, исторические dailyCapacity/dailyWorkloads и прошлые проценты сохраняются.

При просмотре завершивших работу под именем указана включительная дата последнего рабочего дня из закрытого кадрового периода. В таймлайне нулевая сегодняшняя занятость поясняется подсказкой. Дневные ячейки команды/отдела показывают в title назначенную работу, доступную мощность конкретного дня и существующий расчёт процента; сумма занятости в боковой панели относится к сегодняшнему дню. Сотрудник без назначенной загрузки всё равно входит в доступную мощность своего кадрового периода.

У прежней строки переведённого сотрудника показано «Переведён с …». Сервер проверяет непрерывную смену отдела/команды по реальным кадровым периодам, включая события вне отображаемого диапазона и промежуточные изменения занятости. Граница диапазона, baseline и завершение работы не считаются переводом. Дополнительное чтение ограничено сотрудниками уже разрешённых исторических строк; на клиент возвращается только дата ухода из соответствующего состава.

Источник текущего статуса — `actions/employment-roster.ts`: авторизованный session-клиент определяет доступные профили, затем сервер читает только их кадровые периоды порциями по 100 ID и страницами по 1000. Завершение определяется по последнему периоду с исключительной границей valid_to, не по занятости или названию роли. Отсутствие кадровых записей не считается завершением.

`useFinishedEmployees` делит TanStack-кэш по текущему дню Минска в пространстве users. Кадровые действия инвалидируют этот namespace; focus и polling обновляют состав. При первой загрузке или ошибке проверки список не выдаёт всех пользователей за действующих.

Скрытие не отключает вход в приложение и не меняет назначенные права. Изменений БД и новых миграций для этого поведения нет. Подробности кадровых операций: [выбор даты изменения](../../docs/features/employee-employment-effective-date.md).
