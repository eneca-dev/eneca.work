# Перспективные работы на графике отделов

Задача: `feature-VN-04`. ТЗ согласовано 27 октября 2026 года.

## Цель

Визуально отличать предварительно запланированные работы от подтверждённых на вкладке «Отделы».

## Требования первой версии

1. В создании и редактировании загрузки есть переключатель «Перспективная работа», по умолчанию выключенный.
2. Признак относится к отдельной загрузке, в том числе внутри «Прочих работ». Он не определяется статусом проекта, цветом, названием или комментарием.
3. На отмеченной полосе видна плашка «Перспектива». Подсказка: «Предварительное планирование. Работа пока не подтверждена».
4. На коротких полосах допустима компактная иконка с пояснением. Ставка, название и комментарий остаются читаемыми. Признак отображается в дневном и месячном масштабе.
5. Отметка сохраняется после перезагрузки и доступна другим пользователям с правом просмотра загрузки.
6. Изменение отметки использует существующие права редактирования загрузки. Новых прав и изменений RLS нет.
7. Снятие отметки сохраняет сотрудника, сроки, ставку и комментарий.
8. Существующие загрузки по умолчанию не являются перспективными. Копирование и разрезание отмеченной загрузки сохраняют признак.

## Расчёт загрузки

Расчёт не меняется: перспективные работы учитываются в процентах, ставках и суммарной загрузке наравне с остальными. Отметка меняет только визуальное обозначение.

## Границы

Без дополнительных фильтров, отдельных итогов и автоматического определения перспективности. Статус проекта «Потенциальный» остаётся отдельным понятием.

## Реализация

- `loadings.is_prospective boolean NOT NULL DEFAULT false` — источник истины.
- Поле проходит через Server Actions, форму, optimistic cache и данные графика.
- SQL-миграция применена к текущей Supabase после отдельного согласования и зарегистрирована как `20261027121015_add_loading_is_prospective`.
- Типы БД сверены с фактической схемой. Автоматическая генерация через `npm run db:types` недоступна текущему Supabase-аккаунту из-за ограничения прав, поэтому поле синхронизировано вручную.

## Приёмка

- [ ] Переключатель работает при создании, пакетном создании и редактировании.
- [ ] Две загрузки одного проекта отмечаются независимо.
- [ ] Изменение только отметки позволяет сохранить форму; снятие сохраняется как `false`.
- [ ] После повторного открытия и перезагрузки признак сохраняется.
- [ ] Плашка/иконка различима в обоих масштабах и не перекрывает данные.
- [ ] Копирование и обе части разрезанной загрузки сохраняют признак.
- [ ] Ошибка сохранения откатывает оптимистичное изменение.
- [ ] Пользователь без права редактирования не может менять отметку.
- [ ] Показатели загрузки до и после переключения одинаковы.

## Проверки и выпуск

Целевые unit/component/contract-тесты, проверка типов изменённого контура и diff. Build и lint — только по отдельной просьбе. Коммит агент не создаёт.
