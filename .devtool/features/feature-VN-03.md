# feature-VN-03 Компактный вид, выбор даты и выделение расчётной группы на вкладке «Занятость»

## Цель

Сделать доску занятости компактнее, дать возможность смотреть состав загрузок на выбранную дату по часовому поясу Минска и визуально отличать сотрудников команды «Расчётная группа».

## Продуктовые правила

- По умолчанию выбрана текущая дата Минска.
- Автоматическая загрузка входит в выбранный день при `loading_status = 'active'`, `is_shortage = false`, `loading_start <= selectedDate` и `loading_finish >= selectedDate`.
- Текущая дата обновляется в минскую полночь, при `focus` и `visibilitychange`; выбранная дата следует за ней только в режиме `followsToday`.
- Manual placements видны и изменяются только сегодня.
- Pinned-проекты видны, добавляются и открепляются на любой дате.
- Pin/unpin и placement управляются разными capability-флагами.
- Принадлежность к расчётной группе определяется только точным `teamName === 'Расчётная группа'`.
- Права, RLS и область видимости отделов не меняются.
- Изменений схемы БД не требуется.

## План реализации

Этап 2 объединяет ранее раздельные этапы подключения кэша и серверной выборки: обязательная дата, режим, TanStack/Redis/build-lock и сборка доски вводятся одной согласованной цепочкой.

### 1. Дата и состояние вкладки

- Добавить строгую проверку существования даты `YYYY-MM-DD` и форматирование подписей «Сегодня», «2 октября», «8 октября 2026».
- Создать `useEmploymentBoardDate(tabId)` с отдельными `currentMinskDate`, `selectedDate` и `followsToday`.
- Сбрасывать дату на сегодня при смене пользовательской вкладки «Занятость».
- При ответе через минскую полночь сверять режим при отправке, режим ответа и режим на момент получения; при расхождении обновлять текущий день и повторять запрос нового ключа.

### 2. TanStack Query и Redis

- Сделать выбранную дату обязательным аргументом хука и Server Action.
- Добавить в TanStack-, Redis- и build-lock-ключи дату и режим `today | dated`.
- Перевести namespace Redis-снимков на `v2`.
- Обычный режим сохраняет cache-aside.
- `realtime-refresh` полностью обходит Redis: не читает version и snapshot, не получает build-lock и ничего не записывает.
- Не префетчить соседние даты; установить ограниченный `gcTime` доски около пяти минут.
- Redis TTL остаётся 60 секунд от момента записи снимка. Строгой границы свежести от момента изменения `loadings` для нового посетителя нет; поздняя старая сборка может записать снимок после события.

### 3. Серверная выборка и сборка

- Использовать выбранную дату во включительных фильтрах `loading_start`/`loading_finish`.
- В режиме `dated` не читать manual placements.
- Извлечь чистую сборку `EmploymentBoard` из Server Action без дублирования SQL-фильтрации.
- Возвращать в ответе фактически вычисленные сервером `selectedDate` и `dateMode`.
- Сохранить текущую фильтрацию restricted-проектов, разрешений и отделов.

### 4. Realtime и гонки

- Оставить глобальный `RealtimeSync` единственной Supabase-подпиской на `loadings`.
- Убрать конкурирующий обычный refetch employment-board для событий `loadings` и передавать активной доске локальный типизированный сигнал.
- Отбрасывать только доказуемо нерелевантные INSERT; UPDATE, DELETE и неполный payload обновляют доску.
- Использовать debounce, один активный fresh-запрос и не более одного trailing refresh.
- После первого релевантного события обходить Redis до размонтирования доски.
- Защитить TanStack через request generation, дату и режим от поздних ответов.
- При любом событии `loadings` удалять неактивные снимки `employmentBoard.lists()` без refetch, не затрагивая presence и поиск.
- Если INSERT нерелевантен активной дате, установить `requiresFreshOnDateChange`; перед следующей сменой даты атомарно включить обход Redis.
- Rollback optimistic mutation не восстанавливает snapshot, если Realtime удалил ключ или изменил cache generation.

### 5. Действия

- `canManageProjects = hasEditPermission`.
- `canManagePlacements = hasEditPermission && dateMode === 'today'`.
- Ограничить placement optimistic update сегодняшним ключом; проектные optimistic update могут затрагивать все даты отдела.
- Серверную проверку даты placement использовать как защиту от команды устаревшего UI, отдельно от проверки `employment_board.edit`.

### 6. Интерфейс

- Добавить календарь выбора одной даты и действие «Сегодня».
- Локально уменьшить padding и gaps, не меняя глобальные стили.
- Уменьшить ширину боковой панели примерно до `16rem`.
- Не уменьшать основной текст сотрудников ниже 12 px.
- На ширине меньше `md` переносить панель наверх и ограничивать её высоту `min(40dvh, 20rem)`.
- Разделить прокрутку списка сотрудников и карточек; сохранить 1/2/3 колонки.
- Централизованно выделить расчётную группу в `EmployeeChip`, сохранив manual/free признаки и добавив `title`/`aria-label`.

## Критерии готовности

- Сегодня отображает тот же автоматический состав, что и до изменения.
- Границы начала и окончания загрузки включительны.
- Данные разных дат и режимов не смешиваются в TanStack и Redis.
- Открытая доска после релевантного Realtime-события не возвращается к Redis до размонтирования.
- Ранее просмотренная дата после события `loadings` читается fresh, а не из старого Redis-снимка.
- Manual placements доступны только сегодня; pin/unpin — на любой дате.
- Расчётная группа различима в панели и карточках без потери manual/free признаков.
- На ноутбуке видно больше контента; узкий и низкий viewport не обрезает панель или карточки.
- Все обязательные unit, contract, integration, component и Playwright-тесты проходят без skipped критических сценариев.
- README модуля документирует дату, режимы, realtime-bypass и точную TTL-гарантию.
