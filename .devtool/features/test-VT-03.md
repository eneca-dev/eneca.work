# test-VT-03 Тест вкладки «Отделы» (/tasks): функционал, сетевые запросы и оптимизация

Родительская задача: **bug-VT-02**. Тестируем по правилам из `bug-VT-02` («Человек + Нейросеть»).

## Цель
Полностью прогнать вкладку «Отделы» в модуле `tasks`: **все панели, компоненты, действия и состояния** + разобрать **каждый сетевой запрос**, найти лишние/дублирующиеся/тяжёлые запросы и предложить оптимизации. На каждый подтверждённый дефект или находку — отдельный тикет `bug-...` со ссылкой сюда.

## Контекст реализации (для проверяющего ИИ)
- Маршрут: `app/(dashboard)/tasks/page.tsx` → `TasksView` → при `viewMode === 'departments'` рендерит `DepartmentsTimelineInternal` (модуль `modules/departments-timeline`).
- Server Actions в Next.js App Router идут как **POST на текущий маршрут `/tasks` с заголовком `Next-Action`** — различаем их по этому заголовку и по телу ответа.
- **Условие загрузки:** таймлайн НЕ грузится, пока нет фильтров и не нажата кнопка «Загрузить всё».
- Ожидаемые запросы при работе вкладки:
  - `getDepartmentsData(filters)` — основная тяжёлая выборка (орг.структура + `view_employee_workloads` + гранты). `staleTime: Infinity` (обновление только через Realtime/invalidation), queryKey `departmentsTimeline.list(filters)`.
  - `getTeamsFreshness()` — актуальность команд, `staleTime: 5 мин`, queryKey `departmentsTimeline.freshness()`.
  - `useCompanyCalendarEvents` (из `resource-graph`) — события календаря компании (праздники/переносы), `staleTime: 24ч`.
  - `reloadPermissions()` — вызывается в `TasksView` на маунте (useEffect) → возможный источник лишних запросов/рефетча.
- Мутации и их инвалидация:
  - `updateLoadingDates` (drag-resize) → optimistic + invalidate `departmentsTimeline.all` + `sectionsPage.all`.
  - `bulkShiftLoadings` → N апдейтов `loadings` батчами по 10 + invalidate тех же ключей.
  - `confirmTeamActivity` / `confirmMultipleTeamsActivity` → invalidate `departmentsTimeline.freshness()`.
  - `useLoadingMutations` (create/edit/split) из `modules/modals`.
- Realtime-подписки модуля (см. `modules/cache/realtime/config.ts`).

### Карта UI-поверхности (что проверяем)

- **Таймлайн:** фоны дней (выходные/праздники/today), полосы загрузки % (зелёный/жёлтый/красный), `LoadingBarWithResize` (bar + ручки ресайза + rate-бейдж + комментарий + штриховка нерабочих дней + чекмарк выбора), месячный режим `MonthlyLoadingBars`.

## Результаты и отчет тестирования
**Сводка:** Вкладка "Отделы" функционально работает отлично (проверены сценарии F1-F47: состояния, скролл, сдвиги, иерархия, права). Однако выявлены серьезные проблемы с производительностью из-за чрезмерного количества вызовов Server Actions (`POST /tasks`). Практически каждое UI-действие (включая чисто клиентские, вроде сворачивания списков) вызывает цепочку серверных запросов.

**Подтвержденные проблемы:**
1. Шторм из 14+ запросов при маунте страницы.
2. Отсутствие кеширования при переключении вкладок.
3. Лишние запросы при работе с фильтрами и сворачивании списков.
4. Тяжелый рефетч вместо точечной инвалидации после `drag-to-resize`.
5. Расхождение логики цветов загрузки со спецификацией.
6. (Проверка пройдена) Realtime-подписки работают отлично, UI обновляется мгновенно. Варнинг `No session` в консоли является ложным срабатыванием на первом рендере.

**Предложения по оптимизации:**
- Использовать `useMemo` / `useCallback` и проверить зависимости в `useEffect` для устранения циклических вызовов экшенов.
- Для фильтров использовать нормальный дебаунс (например, хук `useDebounce`).
- Изучить логику `revalidatePath` / `revalidateTag` при ресайзе: она слишком широкая и инвалидирует все данные.
- Починить инициализацию Supabase-клиента для Realtime, чтобы он корректно подхватывал сессию.
