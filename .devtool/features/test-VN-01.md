# test-VN-01 Тест модуля «Встречи» (/meetings): функционал, сеть, БД

Тестируем по правилам «Человек + Нейросеть» (как в `test-VT-03`): тестировщик кликает, ИИ ведёт сценарии, читает console/network через Playwright MCP и проверяет данные. На каждый подтверждённый дефект — отдельный тикет `bug-VN-NN` со ссылкой сюда.

## Цель
Полностью прогнать модуль «Встречи»: список созвонов, просмотр протокола, скачивание `.docx`, поиск+подсветка, папки (фильтр/CRUD/назначение/персистентность), шеринг и видимость, адаптив/панели, сайдбар. По каждому действию разобрать сетевые запросы (лишние/дубли) и состояние данных.

## Контекст реализации (для проверяющего ИИ)
- Маршрут: `app/(dashboard)/meetings/page.tsx` → `MeetingsPanel` (модуль `modules/meetings`). 2 панели: список (фильтр папок + поиск) | просмотр протокола.
- **Данные:** `getMeetingReports` (Server Action, идёт как `POST /meetings` с `Next-Action`) читает таблицу `meeting_reports` из **отдельного** Supabase-проекта через service-role (`modules/meetings/server/meetings-client.ts`).
- **Видимость:** созвон виден владельцу (`invited_by_email` = email пользователя; для `fopeto72@gmail.com` — алиас на `vladzimir.nesterovich@enecagroup.com`) **или** тому, кому расшарено. Поле `isOwner` с сервера.
- **Шеринг:** `shareReport`/`unshareReport`/`getReportShares`; таблица `meeting_report_shares` (в meetings-проекте); только владелец.
- **Папки:** локальные (zustand persist, localStorage `meetings-folders`): фильтр (`Все/Без папки/папка`), модалка CRUD, назначение созвона в папку.
- **Протокол:** рендер `report` (jsonb) — summary/участники/обсуждение/вопросы/риски; кнопки скачать `protocol_docx_url`/`transcript_docx_url`.
- **Поиск:** клиентский по теме/участникам/тексту; подсветка в названии и в тексте.
- **Панели:** `react-resizable-panels`, ширины в localStorage (`meetings-panels-reports`). Realtime для meetings отключён.

## Среда
- `localhost:3000`, dev, тестировщик авторизуется сам (залогинен как Владимир Нестерович / `fopeto72@gmail.com`).
- Браузер ведёт ИИ через Playwright MCP; тестировщик кликает/подтверждает.
- ИИ читает console + network через Playwright. **Supabase MCP не подключён** — проверки БД meetings-проекта делаем через SQL, который выполняет тестировщик.

### 🔒 Безопасность
- [ ] **SEC1. Service-role ключ не утекает.** `MEETINGS_SUPABASE_SERVICE_ROLE_KEY` отсутствует в клиентском бандле/Network (не `NEXT_PUBLIC`); `meetings-client` только на сервере. Проверить grep по JS-бандлу/Network.
- [ ] **SEC2. Видимость только своих + расшаренных.** Под другим аккаунтом чужие созвоны не видны; нельзя получить чужой по `id`.
- [ ] **SEC3. Шеринг только владельцем.** `shareReport/unshareReport` для чужого созвона (подделанный `reportId`) → отказ (`assertOwner` на сервере); не-владелец не видит кнопку «Поделиться».
- [ ] **SEC4. Auth-гейт.** Без сессии `getMeetingReports` → «Не авторизован»/редирект на логин (S1 косвенно подтвердил).
- [ ] **SEC5. Подписанные .docx.** `protocol_docx_url`/`transcript_docx_url` — временные signed-URL (`token`+`exp`), не публичные постоянные.
- [ ] **SEC6. XSS в протоколе.** `report` рендерится как структура (без `dangerouslySetInnerHTML`); спецсимволы/HTML в полях текста не исполняются.
- [ ] **SEC7. IDOR.** Прямой вызов Server Action с чужим `reportId` не отдаёт данные и не даёт управлять доступом.

> Часть проверок безопасности/оптимизации ИИ-driven: SEC1 — grep по сборке/Network; SEC2/3/7 — попытки несанкционированного доступа; P1/P3 — Network + прод-сборка; БД — через SQL тестировщика.
