# bug-VN-08 Сортировка команд в списке пользователей

## Задача

В группировке «Подразделения → Отделы → Команды» страницы «Пользователи» показывать команды внутри отдела по возрастанию названия с учётом чисел: 1, 2, …, 10. Названия без чисел, включая «Расчётная группа» и «Без команды», располагаются по русскому алфавиту.

## План

Сортировать новый массив Object.entries(teams) непосредственно перед отображением. Состав и порядок сотрудников внутри команд, порядок отделов и подразделений не менять. Запросы, кэши, загрузки, кадровая история и расчёты не затрагиваются. Миграций и изменений данных БД нет.

## Проверки

- [x] Проверен фактический comparator из компонента: числовой и русский алфавитный порядок, регистр, пустой список, неизменность исходного объекта и ссылок на массивы сотрудников (Node assertions).
- [x] 6 существующих тестов users-page.employment.test.tsx прошли; они проверяют сохранность поведения списка и кадрового фильтра, а не порядок команд.
- [x] Clean Code Guardian: Approved, замечаний нет. git diff --check прошёл.
- [ ] Ручная проверка списка пользователем.

Build, lint, dev и коммит автоматически не запускать.

## Как решена проблема

В users-list.tsx новый массив Object.entries(teams) сортируется перед map через localeCompare с локалью ru, numeric: true и sensitivity: base. Исходный объект групп и массивы сотрудников не сортируются и не изменяются. Единственная правка production-кода находится в JSX вывода команд.

## На что обратить внимание ревьюеру

Открыть «Пользователи», включить группировку по подразделениям и развернуть отдел с нумерованными командами. Проверить последовательность 1, 2, …, 10 и алфавитное положение «Расчётной группы». Состав и порядок сотрудников внутри команд, счётчики и порядок отделов должны оставаться прежними. Запросы, серверные actions, БД, кадровая история и формулы загрузки не менялись. Build и ручная проверка ещё не выполнялись.
