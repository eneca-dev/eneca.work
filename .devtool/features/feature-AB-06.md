# feature-AB-06 Занятость вместо счётчиков на строке отдела/проекта

## Проблема
1. На строке отдела бейдж «N пр. · N разд. · N сотр.» (`DepartmentRow.tsx:127`) не отвечает на главный вопрос — сколько сотрудников отдела реально заняты работой прямо сейчас относительно штата отдела.
2. На строке проекта аналогичный бейдж «N разд. · N сотр.» (`ProjectRow.tsx:152`) — избыточный шум, дублирующий то, что и так видно по развёрнутому дереву.

## Решения (согласованы с постановщиком)
1. Бейдж на строке отдела заменяется на **«занято X из Y (Z на непроектных)»**:
   - **Y** — весь штат отдела (все профили с `department_id` = этот отдел, независимо от того, есть ли у них загрузки). Источник — `view_organizational_structure.department_employee_count`, уже используется точно в этом смысле в `modules/departments-timeline/actions/index.ts:557` (`totalEmployees: item.department_employee_count || 0`).
   - **X** — сколько из штата загружены **именно сегодня** (диапазон загрузки включает текущую дату), а не «есть хоть одна загрузка где-то в видимом диапазоне». Иначе число будет «плавать» при переключении День/Неделя (видимый диапазон день-режима ~300 дней, недельного ~16 недель) и при горизонтальном скролле.
   - **Z** — сколько из X заняты **только** служебными «проектами»-корзинами (Отпуск / Прочие работы / Непроектные загрузки — тот же список, что и `SPECIAL_PROJECT_NAMES` в `modules/sections-page/utils/sort-projects.ts:57`).
2. Бейдж на строке проекта убирается совсем, без замены.

## Технический план

### `modules/sections-page/actions/index.ts`
Сейчас `department.totalEmployees` — это `deptEmployeeIds.get(dept.id)?.size` (строка ~621), т.е. «у кого есть хоть одна загрузка в этой иерархии». Это НЕ штат отдела — оставить это поле как есть для внутренних нужд (сортировка и т.п.), но не путать с новым.

Нужно добавить:
1. **Штат отдела** — отдельный запрос к `view_organizational_structure` (по образцу `modules/departments-timeline/actions/index.ts:172`) с `.in('department_id', deptIds)` по всем отделам текущей выборки одним запросом (не N+1) → новое поле `Department.departmentHeadcount`.
2. **Занят сегодня** — второй трекер `Map<deptId, Set<employeeId>>`, отдельный от текущего `deptEmployeeIds`: сотрудник попадает в него, если у него есть загрузка с `loading.startDate <= сегодня <= loading.endDate`. «Сегодня» — `new Date()` в часовом поясе Europe/Minsk (см. `lib/timezone-utils.ts`); `actions/index.ts` — server action, а не workflow-скрипт, обычный `new Date()` тут разрешён.
3. **Занят только на непроектных** — среди попавших в трекер (2), подмножество, у кого ВСЕ активные сегодня загрузки лежат на `project.name`, входящем в `SPECIAL_PROJECT_NAMES`. `isSpecialProject()` сейчас приватная в `sort-projects.ts` — экспортировать её оттуда, чтобы не дублировать список названий.

### `modules/sections-page/types/index.ts`
`Department` — добавить поля:
```ts
departmentHeadcount: number       // весь штат (view_organizational_structure)
busyTodayCount: number            // занято сегодня
busyOnNonProjectCount: number     // из них — только на непроектных
```

### `modules/sections-page/components/rows/DepartmentRow.tsx`
Строка 127 — заменить:
```tsx

```
на:

### `modules/sections-page/components/rows/ProjectRow.tsx`
Строка 152 — удалить блок бейджа целиком (`<div className="text-xs text-muted-foreground bg-muted/50 px-2 py-0.5 rounded">...</div>`), оставить в правой части строки только то, что было слева (иконка + название + РП).

## Риски
- Запрос штата отдела — лишний round-trip к БД на странице «Разделы» (сейчас там нет обращений к `view_organizational_structure`). Собрать одним запросом по всем `deptIds` сразу, не по одному на отдел.
- Если у пользователя открыта страница дольше суток без обновления (React Query кэш), «занято сегодня» может на несколько минут отставать от полуночи — не критично, страница и так не realtime посекундно.
- Не обсуждали явно: как считать загрузку с `rate = 0` — вероятно, как «занят» (запись существует), но стоит уточнить, если такой кейс всплывёт на реальных данных при ревью.

## Оценка масштаба
2 изменяемых файла в `actions`/`types` (новый запрос + 2 трекера) + точечные правки в 2 UI-компонентах. Без миграций БД — используется существующий view.

## Как решено
Реализовано по плану, плюс несколько правок после прогона Cache Guardian и Clean Code Guardian по диффу:

- **Запрос штата** переехал перед построение иерархии и запускается через `Promise.all` вместе с уже существующим запросом `employeeTeamMap` (`view_users`) — вместо отдельного round-trip'а после всей остальной обработки, как было в изначальном плане. `deptIds` для него собираются из сырых строк ответа (`department_id` ∪ `employee_department_id`), а не из уже построенной иерархии — не нужно ждать окончания цикла.
- **Ошибка запроса штата больше не проглатывается молча** — при сбое логируется + уходит в Sentry, и `departmentHeadcount` уходит в `null` вместо тихого "из 0".
- **Несоответствие масштаба X и Y** (найдено Cache Guardian): `busyTodayCount` может быть уже сужен фильтром `team_id`/`project_id` (например, показывается только одна команда отдела), тогда как штат отдела (`departmentHeadcount`) — всегда весь отдел целиком. Показ обоих чисел вместе в этом случае вводит в заблуждение («занято 2 из 57» при фильтре по одной команде). Решение: `Department.departmentHeadcount` теперь `number | null` — `null`, когда штат недоступен ИЛИ активен сужающий фильтр; `DepartmentRow.tsx` в этом случае показывает только «занято X» без «из Y».
- **`todayStr`** переведён с `now.toISOString().slice(0, 10)` (UTC) на `formatMinskDate(now)` — по конвенции проекта (Europe/Minsk), и заодно чтобы «занято сегодня» не путалось с UTC-полночью. Заодно поправлен и `staleCutoffStr` (та же функция, тот же файл, тот же баг) — используется существующей с AB-05 логикой `isStale`, не новый функционал этой задачи, но исправление однострочное и в том же месте.
- **Dead code** (найдено Clean Code Guardian): после замены/удаления бейджей поля `Department.totalProjects`, `Department.totalSections`, `Department.totalEmployees` и `Project.totalSections`, `Project.totalEmployees` перестали где-либо читаться (проверено `grep` по всему `modules/sections-page`). Удалены из типов и из вычисления в `actions/index.ts`, вместе с трекерами `deptEmployeeIds`/`projectEmployeeIds`, которые только их и заполняли.

## На что обратить внимание ревьюеру
1. **Обязательно вручную:** страница «Разделы» без фильтров — бейдж отдела должен показывать «занято X из Y», где Y — реальный штат (сверить с страницей «Отделы», там то же число уже показывается как штат). С активным фильтром по команде или проекту — бейдж должен показывать только «занято X» без «из Y» (осознанное решение, не баг).
2. Отдел без ни одной активной сегодня загрузки, но с загрузками на «Отпуск»/«Прочие работы» — проверить, что они корректно попадают в «Z на непроектных», а не пропадают из X.
3. Проверить полночь по Минску (00:00–03:00) — раньше `todayStr` в этом окне отставал на день (UTC-баг), теперь должен считать корректно; не самое важное для этой конкретной фичи, но задевает существующую логику `isStale`/сортировки из AB-05.
4. Убедиться, что `npm run build` проходит — правки в `actions/index.ts` затрагивают экспортируемый тип `Department` (`departmentHeadcount: number | null`), стоит проверить, что нигде больше в репо не создаются объекты этого типа без нового поля (искала — только этот файл его создаёт).
