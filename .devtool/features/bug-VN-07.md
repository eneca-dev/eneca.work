# bug-VN-07 Скрытие завершивших работу из текущего состава

## Согласованное поведение

Пользователь выбрал сохранение профиля и кадровой истории вместо физического удаления. Завершившие работу скрыты по умолчанию из списка пользователей и текущего состава в «Отделах». Их можно показать отдельным переключателем; полностью прошлый диапазон таймлайна показывает исторический состав. Последний рабочий день включён: скрытие начинается со следующего дня. Прошлые проценты, загрузки, профиль и доступ к аккаунту этим изменением не удаляются и не меняются.

## План

- Серверное чтение завершивших работу только среди доступных session-клиенту профилей, с ограниченными UUID-запросами и пагинацией. Определять по последнему периоду, не по ставке или названию.
- Общий TanStack query состояния текущего состава: обновление на кадровых мутациях, focus, смене минского дня и polling.
- Скрытие в списке пользователей и строках текущего таймлайна без изменения исходных кэшей, исторических агрегатов и прав.
- Явный просмотр завершивших работу, состояния загрузки/ошибки без показа их как действующих.
- Проверки границы дня, неизвестных профилей, исторических итогов, permissions и UI.

## Критерии

- [x] Пользователь, чей последний день вчера, скрыт в текущих списках.
- [x] Последний день сегодня включён.
- [x] Профиль без кадровых периодов не считается завершившим работу автоматически.
- [x] Исторические проценты не меняются; прошлый диапазон и переключатель показывают историю.
- [x] Ошибка проверки состава не превращается в показ всех как действующих.
- [x] 32 автоматических теста, целевые проверки TypeScript без ошибок, проверка агентом без блокеров.
- [ ] Build и ручная приёмка пользователем.

Миграций и изменений рабочей БД нет. Коммит не создавать.

## Как решена проблема

Согласованная пометка перевода: annotateEmployeeTransfers после разрешённой исторической проекции обогащает только прежние own-membership строки transferredOn. Проверяет реальные смежные периоды с изменением department/team, проходит rate-only цепочки за пределами viewport и берёт последнюю дату ухода из данной membership. Baseline/разрывы/finish без продолжения не дают ложной даты. Read-only запросы по уникальным уже разрешённым IDs (100 за запрос, страницы 1000), назначения и остальные периоды не возвращаются на клиент. EmployeeRow показывает «Переведён с …» и поясняет ноль в прежнем составе. 48 focused тестов в четырёх файлах прошли; целевые типы без ошибок. БД и расчётные формулы не менялись.

Дополнительно согласовано скрытие прежних строк после перевода. filterCurrentEmployeeRows сравнивает контейнер отдела/команды с уже имеющимися currentDepartmentId/currentTeamId, не меняя агрегаты и данные. Гостевые строки по грантам и дефицит сохраняются; legacy без текущих metadata не скрываются наугад. Для null-команды учитывается synthetic unassigned. В «Отделах» переключатель переименован в «Показывать историю состава», показывающий переведённых и завершивших работу; полностью прошлый диапазон автоматически сохраняет все исторические строки. 16 focused unit/component тестов прошли, целевой TypeScript без ошибок. Ручная проверка переведённого Вадима ещё нужна. Изменений БД нет.

Пользователь дополнительно согласовал пояснения. Reader возвращает finishedOnByEmployeeId с включительной датой valid_to−1 в UTC, только для ранее разрешённых завершивших работу профилей. Общий EmploymentFinishedLabel используется в таблице пользователей и таймлайне. Нулевая сегодняшняя занятость архивной строки имеет пояснение. Общий форматтер дневной ячейки объясняет уже рассчитанный процент через workload/capacity конкретного дня, включая сотрудников без назначений; zero-base и нерабочие дни объясняются отдельно. Расчётные формулы и данные не менялись.

Добавлен server reader getFinishedEmployees с session-auth, ограничением IDs областью видимости view_users и чтением последнего кадрового периода через service-role. Shared hook использует отдельные ключи users/finished-employees с текущим минским днём, общий сброс users после мутаций, focus и polling. Страница пользователей фильтрует только производный список, не меняя raw fullList и собственную карточку. Таймлайн фильтрует только видимые own/guest строки, сохраняя исходные historical aggregates. Обе страницы имеют переключатель; полностью прошлый диапазон автоматически показывает всех исторических сотрудников.

## На что обратить внимание ревьюеру

- valid_to исключительный: последний рабочий день виден, скрытие со следующего дня.
- Отсутствие истории не равно завершению; поздний открытый период отменяет вывод по старому закрытому.
- Исторические проценты могут включать скрытого по умолчанию сотрудника; переключатель/прошлый диапазон позволяют увидеть его вклад.
- Scope изменения — список пользователей и таймлайн «Отделы». Назначенные роли, аккаунт и доступ не отзываются; admin-справочники не перерабатывались.
- 32 теста в пяти файлах, целевые TypeScript-проверки и git diff --check прошли. Build/lint/dev и коммит не запускались.
- Ручная проверка: Тест Истории завершил работу 24 ноября и 25 ноября скрыт по умолчанию; включение переключателя возвращает его. Проверить текущий и прошлый диапазоны и сохранность итогов. Рабочую БД для тестов не изменяли.
