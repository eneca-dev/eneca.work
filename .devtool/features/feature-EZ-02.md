# feature-EZ-02 Диаграмма Ганта для этапов проекта (Project Diagram)

Родительский тикет. Новый модуль/представление для управления сроками этапов декомпозиции в иерархии проект → объект → раздел → этап.

---

## Контекст и проблема

Сейчас у команды нет единого интерфейса для визуального управления сроками этапов декомпозиции. РП/ГИП вынуждены пользоваться внешними инструментами (Google Sheets, MS Project) для построения временны́х планов по этапам.

Задача — создать встроенную диаграмму Ганта, где:

- Видна иерархия: **Проект → Объект → Раздел → Этап**
- Этапы со сроками отображаются на временно́й шкале
- Этапы **без сроков** вынесены в отдельный список и могут быть размещены на шкале перетаскиванием
- Управление сроками — прямо на диаграмме, без открытия модальников

---

## Структура данных

Иерархия (существующая в БД):

```
Проект (projects)
  └─ Объект (objects)
      └─ Раздел (sections)
          └─ Этап декомпозиции (decomposition_stages)
               startDate / endDate — сроки этапа
```

> **Важно:** `stage_id` у проекта — это параметр (стадия проектирования, напр. «ОТР», «Стадия А»), а **не** уровень иерархии. В этом тикете Stage как отдельный уровень **не используется**.

#### Левая колонка (sidebar) — иерархия + pills

- Фиксированная ширина (аналог `SIDEBAR_WIDTH` из resource-graph)
- Строки проекта и объекта — только название, сворачиваются/разворачиваются кликом
- Строка раздела содержит: **название раздела сверху** + **pills бессрочных этапов снизу** (wrap по ширине sidebar)
- Этапы со сроками в sidebar не отображаются — только на таймлайне

#### Строка раздела — единый блок переменной высоты

Строка раздела **не фиксирована по высоте**. Высота определяется максимумом из:

- количества строк баров на таймлайне (stacking перекрывающихся этапов)
- количества строк pills в sidebar-ячейке

Обе ячейки (sidebar и таймлайн) для одного раздела всегда имеют **одинаковую высоту**.

```
┌─────────────────────┬──────────────────────────────────────────┐
│  Sidebar (иерархия) │  Временна́я шкала                         │
├─────────────────────┼──────────────────────────────────────────┤
│                     │                                          │
│  Раздел «АР»        │        ▓▓▓▓▓ Этап А ▓▓▓▓▓               │
│                     │            ▓▓▓▓▓▓▓ Этап С ▓▓▓▓▓▓▓       │
│  [pill Б] [pill В]  │        ▓▓▓ Этап D ▓▓▓                   │
│  [pill Г] [pill Д]  │                                          │
│                     │                                          │
├─────────────────────┼──────────────────────────────────────────┤
│  Раздел «КЖ»        │        ▓▓▓▓▓▓▓▓ Этап X ▓▓▓▓▓▓▓▓        │
│  [pill Y] [pill Z]  │                                          │
└─────────────────────┴──────────────────────────────────────────┘
```

**Sidebar-ячейка раздела:**

- Сверху — название раздела
- Снизу (или заполняя оставшееся пространство) — pills бессрочных этапов, расположенные в несколько рядов (wrap), выровненные по левому краю
- Если бессрочных этапов нет — нижняя часть ячейки пустая
- Ячейка тянется по высоте вместе с таймлайн-ячейкой

**Таймлайн-ячейка раздела — бары (срочные этапы):**

- Позиционируются по `startDate`/`endDate` относительно временно́й шкалы
- Название этапа выводится **прямо на баре** (truncate + tooltip если бар короткий)
- Сроки читаются из шкалы сверху — отдельной подписи дат на баре нет
- Перекрывающиеся по времени бары укладываются на отдельные горизонтальные строки (stacking) — отсюда и растёт высота блока

**Drag pill → таймлайн:**

- Pill перетаскивается из sidebar-ячейки на сетку таймлайна
- Устанавливает `startDate` = дата drop, `endDate` = +7 дней
- Pill исчезает из sidebar-ячейки, этап появляется баром на шкале

#### Временна́я шкала (header)

- Верхний ряд: месяц + год
- Нижний ряд: дни / недели / месяцы (зависит от выбранного масштаба)
- Вертикальная линия «сегодня» поверх всей сетки

### 3. Обязательные возможности взаимодействия

| #   | Функциональность              | Описание                                                                                                                                                                                                        |
| --- | ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | **Скролл по X и Y**           | Вертикальный скролл по строкам иерархии (левая колонка и таймлайн синхронизированы) + горизонтальный скролл по временно́й шкале                                                                                  |
| 2   | **Масштабирование (Scale)**   | Переключение масштаба шкалы: день / неделя / месяц / квартал. Кнопки ± в верхней панели фильтра. Опционально: Ctrl + колёсико мыши.                                                                             |
| 3   | **Перетаскивание краёв бара** | Drag левого/правого края бара этапа — изменение `startDate` / `endDate` в реальном времени (предпросмотр даты при drag), сохранение по отпусканию (Server Action)                                               |
| 4   | **Drag pill → таймлайн**      | Перетаскивание pill (бессрочного этапа) из строки раздела на временну́ю сетку: автоматически устанавливает `startDate` = дата drop, `endDate` = +7 дней. Pill исчезает из зоны pills, появляется баром на шкале. |

### 4. Группировка и сворачивание

- Строки иерархии (Проект / Объект / Раздел) сворачиваются/разворачиваются кликом
- Collapsed-строка суммарно показывает **сегментированный бар** по дочерним этапам: каждый этап — отдельный сегмент на шкале, между ними видны gaps (периоды без работ). Не один сплошной диапазон min–max, а реальная картина занятости.

### 5. Индикация

- Название этапа — отображается **прямо на баре** (truncate с tooltip если не помещается)
- Pills бессрочных этапов — в начале строки раздела, до зоны баров
- Текущая дата — вертикальная линия «сегодня» поверх всей сетки
- Tooltip при наведении на бар: название этапа, раздел, даты, длительность в днях
- Collapsed-строка объекта/проекта: **сегментированный бар** — каждый дочерний этап рисуется отдельным сегментом, gaps между этапами остаются пустыми. Tooltip показывает список этапов с датами.

### Шаг 4 — Архитектура `ProjectDiagram.tsx`

**Состояние:**
```ts
const [scale, setScale] = useState<'day' | 'week' | 'month'>('week')
const [collapsed, setCollapsed] = useState<Set<string>>(new Set())
const scrollRef = useRef<HTMLDivElement>(null)
const [rangeStart] = useState(() => addDays(getTodayMinsk(), -30)) // 30 дней назад
```

**Вычисляется:**
- `ppd` (pixels per day): `{ day: 36, week: 14, month: 5 }[scale]`
- `timelineWidth = 210 * ppd` (210 дней = 30 до + 180 после)
- `todayLeft = 30 * ppd`
- массив `monthGroups` — группировка `DayCell[]` по месяцу для шапки (ряд 1)
- массив `weekMarkers` — понедельники из `DayCell[]` для шапки (ряд 2)
- `stacked = stackStages(section.stages)` — алгоритм: сортировать по startDate, greedy-раскладка по трекам (track = индекс строки внутри раздела)
- `sectionHeight` = `ROW_PAD * 2 + max(кол-во-треков × BAR_H, кол-во-рядов-pills × PILL_H)`

**Разметка (единый `overflow-auto` контейнер):**
```
<div ref={scrollRef} className="overflow-auto flex-1">
  <div style={{ minWidth: SIDEBAR_WIDTH + timelineWidth }}>

    {/* Sticky header: top-0 */}
      {/* Ряд 1: месяцы — corner sticky left-0 | month cells */}
      {/* Ряд 2: недели — corner sticky left-0 | week markers */}

    {/* Строки данных */}
    {rows.map(row =>
      <div className="flex border-b" style={{ height: rowHeight }}>
        {/* Sidebar cell: sticky left-0, z-10 */}
        {/* Timeline cell: relative, width = timelineWidth */}
      </div>
    )}

  </div>
</div>
```

Sticky corner (header × sidebar) реализуется вложенным `sticky left-0` внутри `sticky top-0` — стандартный паттерн для «замороженной» ячейки таблицы в одном scroll-контейнере.

**Типы строк:**

| Тип | height | Sidebar | Timeline |
|---|---|---|---|
| `project` | 38px | chevron + цветная точка + название (жирное) | пустая полоса |
| `object` | 34px | indent + chevron + название (серое) | пустая полоса |
| `section` | динамическая | название раздела + pills (wrap) | stacked бары |

**Алгоритм stacking:**
```ts
// Greedy: сортировать по startDate, для каждого этапа найти первый трек,
// где trackEndDate < stage.startDate. Иначе — новый трек.
function stackStages(stages): Array<{ stage; track: number }>
```

**Бар в ячейке таймлайна:**
- `left`, `width` — через `calculateBarPosition()` или inline через `differenceInDays` × `ppd`
- `top = ROW_PAD + track * (BAR_H + BAR_GAP)`
- Название — внутри бара, `truncate`, показывать только если `width > 50px`
- Resize-handles — `position: absolute` по краям, `cursor-col-resize` (визуально в моке, без логики)

## Review

### Как решена задача

Реализован новый модуль `modules/project-diagram/` с компонентом `ProjectDiagram.tsx` — кастомная диаграмма Ганта на `div`-ах с абсолютным позиционированием. Используются мок-данные (2 проекта, 5 разделов, ~16 этапов). Переиспользованы утилиты из `resource-graph` (`calculateBarPosition`, `generateDayCells`, константы). Реализованы: sticky-шапка с масштабами, sidebar с иерархией и pills, stacking перекрывающихся баров, линия «сегодня», @dnd-kit для drag-and-drop.

### Что проверить ревьюеру

- Корректность sticky-позиционирования шапки и sidebar при горизонтальном и вертикальном скролле
- Алгоритм stacking: перекрывающиеся бары должны раскладываться по трекам без наложения
- Высота строки раздела: определяется максимумом из кол-ва треков и кол-ва рядов pills
- Drag pill → таймлайн: pill исчезает из sidebar, появляется баром
- Масштаб day/week/month: шапка и позиции баров должны корректно пересчитываться
- Импорты из `resource-graph` — убедиться, что не тянутся store-зависимости
