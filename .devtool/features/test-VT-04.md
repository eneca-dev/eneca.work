# test-VT-04 Тест вкладки «Разделы» (/tasks): функционал, сетевые запросы и оптимизация

Родительская задача: **bug-VT-02**. Тестируем по правилам из `bug-VT-02` («Человек + Нейросеть»).

## Цель
Полностью прогнать вкладку «Разделы» в модуле `tasks`: **все панели, компоненты, действия и состояния** + разобрать **каждый сетевой запрос**, найти лишние/дублирующиеся/тяжёлые запросы, дорогие in-memory трансформации и предложить оптимизации. На каждый подтверждённый дефект или находку — отдельный тикет `bug-...` со ссылкой сюда.

## Контекст реализации (для проверяющего ИИ)
- Маршрут: `app/(dashboard)/tasks/page.tsx` → `TasksView` → при `viewMode === 'sections'` рендерит `SectionsPageInternal` (модуль `modules/sections-page`).
- Server Actions в Next.js App Router идут как **POST на текущий маршрут `/tasks` с заголовком `Next-Action`** — различаем их по этому заголовку и по телу ответа.
- **Условие загрузки:** таймлайн НЕ грузится, пока нет фильтров и не нажата кнопка «Загрузить всё» (`shouldFetchData = filtersApplied || loadAllEnabled`).
- Ожидаемые запросы при работе вкладки:
  - `getSectionsHierarchy(filters)` — основная тяжёлая выборка из view `view_departments_sections_loadings` (`select('*')`, плоские строки → иерархия Department → Project → ObjectSection → Loading). `staleTime: Infinity`, queryKey `sectionsPage.list(filters)`.
  - `getFilterContextForTasksTabs()` + `getRestrictedProjectIds()` — контекст прав и restricted-проекты, **параллельно** до основного запроса.
  - **Доп. запрос к `view_users` (`select user_id, team_id`)** уже ПОСЛЕ основного — подтягивает `team_id` для уникальных `employee_id`. Кандидат на лишний водопад.
  - При фильтре `team_id`/`subdivision_id` — цепочка резолвов: `resolveMultiValueToUuids` (teams) → `view_employee_workloads` → `in('employee_id', ...)`. Потенциальный N+1.
  - `useCompanyCalendarEvents` (из `resource-graph`) — праздники/переносы, `staleTime: 24ч`.
  - `reloadPermissions()` — вызывается в `TasksView` на маунте (useEffect) → возможный источник лишних запросов/рефетча.
- Мутации и их инвалидация:
  - `updateLoadingDates` (drag-resize) → optimistic + invalidate `sectionsPage.all` + `resourceGraph.all` + `departmentsTimeline.all`.
  - `useLoadingMutations` (create/update/archive/delete/split) → глубокий optimistic в трёх кешах + invalidate `loadings.all` и тех же трёх ключей.
  - `upsertSectionCapacity` / `deleteSectionCapacityOverride` → invalidate **всех** `sectionsPage.lists()` (слишком широко, без fine-grained по `section_id`).
- Realtime-подписки (см. `modules/cache/realtime/config.ts`): изменения в `loadings`, `sections`, `profiles`, `departments`, `decomposition_stages` инвалидируют `sectionsPage.all` (debounce 100ms).

### Карта UI-поверхности (что проверяем)
- **Заголовок/тулбар:** `ScissorsToggle` (режим ножниц), заглушки «развернуть/свернуть всё» (TODO, скрыты), `TimelineHeader` (даты, popover диапазона, «Сегодня»). **Нет** переключателя день/месяц и **нет** bulk-shift (в отличие от «Отделы»).
- **Иерархия (4 уровня, левый sidebar):** `DepartmentRow` (Building2) → `ProjectRow` (FolderKanban, «РП: …») → `ObjectSectionRow` (Box, объект/раздел) → `EmployeeRow` (аватар, должность, категория, ставка). Метрики-теги на каждом уровне («N пр. · N разд. · N сотр.»). **Дублирование разделов по отделам** в зависимости от scope.
- **Таймлайн:** `AggregatedBarsOverlay` (мини-бары X/Y на Department/Project/ObjectSection с цветовой шкалой загрузки), `LoadingBar` на `EmployeeRow` (цвет по разделу, rate-бейдж sticky, иконки раздел/этап, штриховка нерабочих дней, комментарий, ручки ресайза, линия реза). Фоны дней (выходные/праздники/today).
- **Inline-редактор ёмкости** на `ObjectSectionRow`: клик по ячейке → input (0.1–99), выбор диапазона, сохранение в `useSectionsPageUIStore` + сервер.
- **Модалки:** `LoadingModalNewCreate`, `LoadingModalNewEdit` (из `modules/modals`), popover диапазона дат.
- **Сторы:** `useSectionsPageUIStore` (expandedNodes / capacityOverrides / customDateRange, persist localStorage), `useScissorsModeStore`.
- **Права:** `sections.capacity.edit` (редактор ёмкости), `loadings.edit.scope.*` (drag/scissors/create через `useCanEditLoading`), `hierarchy.is_admin` (restricted-проекты).

## Результаты и отчет тестирования
**Сводка:** Вкладка «Разделы» проверена по всему функционалу (иерархия, inline-редактор, drag-resize, realtime, модалки). Визуальный UI отрабатывает на 10/10: данные дублируются по scope правильно, realtime-обновления долетают успешно, редактирование capacity работает гладко.
Однако, как и на вкладке «Отделы», обнаружены критические проблемы с производительностью (шторм Server Actions).

**Подтвержденные проблемы:**
1. Водопад из 19+ запросов `POST /tasks` при первоначальной загрузке страницы и при возврате с других вкладок.
2. Заметные задержки UI и шквал аналогичных `POST /tasks` запросов при простом клиентском разворачивании/сворачивании узлов иерархии (нарушение Сценария S6).

**Предложения по оптимизации:**
- Устранить источник постоянных `POST` запросов при маунте строк иерархии (вероятно, дело в `reloadPermissions` или неправильных зависимостях `useEffect`).
- Изолировать логику сворачивания так, чтобы она работала чисто через `useSectionsPageUIStore`, не провоцируя перерисовки, вызывающие серверные мутации.
