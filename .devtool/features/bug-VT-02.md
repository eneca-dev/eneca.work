Материнская задача для тестирования приложения.

## Суть тестирования
Взаимодействие человека и нейросети. Нейросеть говорит человеку, что сделать в приложении (например: нажми такую-то кнопку, введи в это поле то-то), смотрит логи через MCP и слушает обратную связь от человека. Все эти тесты проходятся по тикетам, которые создаются заранее.

## Исходные данные для теста
- Запущенное в dev-режиме приложение, открытое через `playwright mcp` в браузере.
- Подключение к логам приложения через Chrome DevTools (`chrome devtools mcp`).

## Правила тестирования (Человек + Нейросеть)

> 🔄 Живой раздел. Дополняется по мере того, как мы уточняем процесс в новых сессиях.

### Роли
- **Человек — тестировщик.** Физически выполняет действия в браузере (тыкает кнопки, вводит данные), следует инструкциям ИИ, сообщает «шаг готов». Авторизуется в приложении сам; ИИ при необходимости подсказывает, где ввести логин/пароль.
- **ИИ — организатор + QA.** Готовит тикеты, ведёт тест по шагам, проверяет качество, заводит баги, отмечает пройденные сценарии.

### Среда
- Тестируем **локально** на запущенном dev-сервере (`localhost:3000`).
- Браузер открывает **ИИ через Playwright MCP**; человек кликает физически именно в этом окне.
- Логи/консоль/сеть ИИ читает через Playwright MCP (console + network); состояние БД — через **Supabase MCP** (только чтение, без изменений без явного согласия).

### Цикл одного теста
1. ИИ заводит тикет на тест (эпик `test`) с чек-листом сценариев.
2. ИИ открывает нужную страницу в Playwright и говорит, с какой кнопки/действия начать.
3. Человек выполняет шаг и сообщает «готово».
4. ИИ проверяет и сравнивает «как должно было отработать» с тем, что реально произошло:
   - **Консоль/логи** — ошибки, варнинги, лишние ре-рендеры, лишние действия.
   - **Сеть** — лишние/дублирующиеся запросы, корректные методы/payload/статусы, время ответа.
   - **БД (Supabase)** — корректность сохранённых данных: таблицы, поля, связи, значения.
   - **Фронт** — отрисовалось ли ожидаемое, совпадает ли UI с данными.
5. Итог шага:
   - **Баг найден** → ИИ заводит отдельный тикет `bug-...` (шаги воспроизведения, ожидаемое/фактическое, артефакты: лог/запрос/скрин).
   - **Бага нет** → ИИ отмечает сценарий галочкой как пройденный и переходит к следующему.

### Оформление тикетов
- Один тикет на тестирование = одна вкладка/фича (можно несколько тикетов на вкладку).
- Все тест-тикеты — подзадачи этой материнской `bug-VT-02`.
- ID, эпики, статусы, версии-лейблы — строго по `AI-RULES.md`.
