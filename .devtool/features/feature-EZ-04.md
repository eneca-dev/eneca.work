# feature-EZ-04 Точки связи на барах, мультивыбор и каскадное перемещение (Project Diagram)

Дочерний тикет `feature-EZ-02`. Расширение диаграммы Ганта: визуальные точки входа/выхода для связей, удаление связи через hover-крестик, топология 1:N и N:1, каскадное перемещение связанных/выделенных баров, выделение прямоугольником и контекстное меню.

---

## Контекст

После реализации базовой отрисовки стрелок (feature-EZ-03) требуется расширить UX взаимодействия со связями и барами. Текущий мок демонстрирует стрелки, но не даёт пользователю явных точек захвата, не поддерживает групповые операции и не каскадирует перемещение.

---

## Что нужно реализовать

### 1. Точки входа и выхода на барах (Connection Points)

На каждом баре постоянно видны два кружка:

```
 ●━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━●
 ↑ start point                  end point ↑
```

- **Start point** — левый край бара (входящая связь, target)
- **End point** — правый край бара (исходящая связь, source)
- Кружки `8px × 8px`, цвет `border: 2px solid #1e7260`, фон `white` (или `bg-background`)
- При наведении на кружок: заливка `#1e7260`, `cursor-crosshair`
- Drag от **end point** → drop на **start point** другого бара создаёт связь FS
- Drag от **start point** → drop на **end point** другого бара создаёт связь FS в обратном направлении

**Видимость кружков — два режима:**

| Режим | Поведение |
|---|---|
| **Hover на баре** | Кружки появляются только на том баре, на который наведена мышь. На остальных барах кружки скрыты. |
| **Drag связи активен** | Кружки скрыты на баре-источнике (он уже «выбран»), но появляются на **всех остальных** барах как зоны drop-таргетов. |

В обоих случаях по умолчанию кружки скрыты (`opacity: 0`, `pointer-events: none`).

**Реализация:**

- Кружки — абсолютно позиционированные `div`-ы внутри бара (`position: absolute`, `top: 50%`, `transform: translateY(-50%)`)
- Видимость управляется через состояние в `ProjectDiagram`: `hoveredBarId: string | null` и `isDraggingLink: boolean`
- Бар показывает кружки если: `hoveredBarId === bar.id` ИЛИ (`isDraggingLink && bar.id !== dragSourceId`)
- Drag через `@dnd-kit` (уже используется в проекте): `useDraggable` на кружке, `useDroppable` на принимающей зоне
- При начале drag от кружка: `isDraggingLink = true`, `dragSourceId = bar.id`; рисуется пунктирная временная линия `GanttLinkDraft` до позиции курсора
- При завершении drag (drop или cancel): `isDraggingLink = false`, `dragSourceId = null`

**Связи 1:N и N:1:**

- Один бар может быть источником для неограниченного числа стрелок (1 end point → N start points)
- Один бар может быть целью неограниченного числа стрелок (N end points → 1 start point)
- Дубликат связи (та же пара from/to) запрещён — при попытке создать дублирующую связь показывается `toast` «Связь уже существует»

### 2. Удаление связи: hover-крестик по центру стрелки

- При наведении мышки на стрелку (`GanttLinkArrow`) по середине линии появляется кнопка `×`
- Кружок `18px × 18px`, фон `white`, иконка `X` из lucide-react, цвет `#6b7280` (hover: `#ef4444`)
- При отведении мышки кнопка исчезает (управляется `useState<isHovered>` внутри `GanttLinkArrow`)
- Клик на `×` удаляет связь из `links` без подтверждения
- `pointer-events: auto` только на кнопке; остальная часть SVG — `pointer-events: none`

**Позиционирование кнопки:**

```
midX = (x1 + x2) / 2
midY = (y1 + y2) / 2
```

Кнопка рендерится как `<foreignObject>` внутри SVG или как абсолютный `div` в оверлейном слое поверх SVG (предпочтительно — `div` во избежание проблем с `foreignObject` в Safari).

### 3. Каскадное перемещение связанных баров

Когда пользователь **drag-resize** (сдвиг бара за тело) одного бара со связями:

- Вычисляется `delta` в днях (разница между новой и старой `startDate`)
- Все бары, на которые указывают **исходящие** связи (children по FS), рекурсивно сдвигаются на тот же `delta`
- Рекурсия: если дочерний бар тоже является источником — его дети тоже сдвигаются
- Обход — BFS/DFS по графу `links` начиная от перемещаемого бара
- Циклы в графе обрабатываются через `Set<stageId>` посещённых вершин

**Важно:** Каскад применяется только при перетаскивании тела бара (изменение startDate/endDate с сохранением длительности). Resize краёв (изменение только одного края) — **не каскадирует**.

**Предпросмотр:** Во время drag все дочерние бары отображаются полупрозрачными на новых позициях (opacity 0.5).

### 4. Выделение баров прямоугольником (Rubber Band Selection)

- Пользователь зажимает ЛКМ на **пустой** области таймлайна (не на баре, не на кружке)
- Рисуется прямоугольник выделения: `position: absolute`, `border: 1.5px dashed #1e7260`, `background: rgba(30,114,96,0.08)`
- Все бары, чей прямоугольник пересекается с прямоугольником выделения, попадают в `selectedStageIds`
- По отпусканию ЛКМ прямоугольник скрывается, выделенные бары подсвечиваются (`ring-2 ring-[#1e7260]`)
- Клик по пустой области снимает выделение

**Дополнительное выделение:**

- Клик на бар добавляет его в выделение (без прямоугольника)
- `Shift + клик` — добавить/убрать один бар из выделения
- Клик на уже выделенный бар без `Shift` — снять всё выделение

**Состояние:**

```ts
const [selectedStageIds, setSelectedStageIds] = useState<Set<string>>(new Set())
const [selectionRect, setSelectionRect] = useState<{ x: number; y: number; w: number; h: number } | null>(null)
```

### 5. Контекстное меню выделенных баров

Когда выделено ≥1 баров, в правом верхнем углу таймлайна (или рядом с последним выделенным баром) появляется плавающая панель:

```
┌────────────────────────────────────────┐
│  ✕ 3 этапа выделено                   │
│  ────────────────────────────────────  │
│  ⊳ Переместить на N дней вперёд/назад  │
│  🔗 Связать выделенные (цепочкой FS)   │
│  ✂ Удалить связи выделенных           │
│  🗑 Удалить этапы (Фаза 2)            │
└────────────────────────────────────────┘
```

- «✕ N этапов выделено» — крестик снимает выделение
- «Переместить на N дней» — поле ввода числа дней + кнопки «←» / «→»; применяет сдвиг ко всем выделенным (как каскад, но без следования связям)
- «Связать цепочкой FS» — создаёт связи между выделенными барами по порядку их `startDate`: бар1→бар2, бар2→бар3 и т.д.
- «Удалить связи» — удаляет все связи, где `fromStageId` или `toStageId` входит в `selectedStageIds`
- Панель — абсолютно позиционированный `div`, `z-index` выше баров

---

### 6. Групповое перемещение выделенных баров

Drag за тело **любого** бара из выделения сдвигает **все** выделенные бары на одинаковый `delta`:

- Во время drag все выделенные бары отображаются на новых позициях (полупрозрачно)
- По завершении drag `startDate`/`endDate` обновляются для всех выделенных
- Если среди выделенных есть бары со связями на **не**выделенные бары — каскад **не применяется** (пользователь управляет группой явно)
- Если все участники связи находятся в выделении — длительность не меняется, все двигаются вместе

## Review

### Как решена задача

Весь функционал реализован в `modules/project-diagram/components/ProjectDiagram.tsx` и `GanttLinks.tsx`.

**Точки входа/выхода (Connection Points):** Кружки встроены в `GanttBarDraggable` как абсолютно позиционированные `div`-ы. Видимость управляется через `isDraggingLink` и `hoveredBarId` в состоянии `ProjectDiagram`. Drag реализован через `@dnd-kit`: `useDraggable` на правом кружке (end point), `useDroppable` — на левом (start point). При начале drag устанавливается `isDraggingLink = true`, `linkDragSourceId`, рисуется `GanttLinkDraft` (пунктирная линия до курсора в `GanttLinks.tsx`).

**Удаление связи через hover-крестик:** В `GanttLinkArrow` (`GanttLinks.tsx`) при `isHovered` рендерится кнопка `×` позиционированная у левого края бара-цели. `pointer-events: auto` только на кнопке — остальной SVG проницаем.

**Каскадное перемещение:** Утилита `getCascadeIds()` — BFS-обход графа связей из `links[]`, возвращает `Set<string>` всех транзитивных дочерних (и родительских) баров. В `handleDragStart` для перемещения тела бара: если бар не в выделении — к нему подключается каскад; если в выделении — двигаются все выделенные. Все сдвигаемые бары добавляются в `movingIdsRef` с исходными датами для корректного расчёта delta.

**Rubber Band Selection:** `mousedown`/`mousemove`/`mouseup` на timeline-зоне (не sidebar) через `handleDataRowsMouseDown`. Активируется только при движении > 4px. Коллизия AABB между прямоугольником выделения и `barRectsRef`. Позиции баров кэшируются в `barRectsRef` через `useMemo`.

**SelectionToolbar (плавающая панель):** Рендерится внизу экрана при `selectedStageIds.size > 0`. Действия: сдвиг на N дней (±), связать цепочкой FS по порядку `startDate`, убрать все связи выделенных, вернуть в список (pill), сбросить даты. Вместо контекстного меню по ПКМ — постоянная панель снизу.

**Групповое перемещение:** Drag тела любого бара из выделения подхватывает всех в `selectedStageIds` — все получают одинаковый `delta` при отпускании.

### Что проверить ревьюеру

- **Connection points:** кружки появляются только при hover на баре (не на всех сразу); при старте drag-связи — появляются на всех барах кроме источника; скрыты по умолчанию (`opacity: 0`)
- **Дублирующая связь:** попытка создать уже существующую пару from/to должна показывать toast «Связь уже существует» и не создавать дубль
- **Hover-крестик на стрелке:** `×` появляется при наведении на стрелку, позиционирован у края бара-цели; клик удаляет связь; SVG при этом не перехватывает клики на барах
- **Каскад vs группа:** drag тела бара без выделения → каскад по FS; drag бара из выделения → двигаются все выделенные (без каскада на связанные-вне-группы)
- **Resize краёв (левый/правый handle) НЕ должен каскадировать** — изменяется только одна дата конкретного бара
- **Rubber Band:** запускается только на пустой области таймлайна; не запускается при клике на бар или кружок; при отпускании — прямоугольник скрывается, выделенные бары получают `ring-2 ring-[#1e7260]`
- **Shift + клик** добавляет/убирает один бар из выделения; клик на выделенный без Shift снимает всё
- **SelectionToolbar:** появляется при ≥1 выделенных; «Связать» создаёт FS-цепочку по возрастанию `startDate`; «Убрать связи» удаляет все in/out связи выделенных
- **Циклы в графе:** BFS-обход должен завершаться (защита через `Set` посещённых вершин), не зависать
