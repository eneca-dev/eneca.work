# bug-DH-11 Игнорирование staleTime при возврате на пикер

## Описание
При переходе со страницы пикера `/tasks` на другую страницу и мгновенном возврате обратно, приложение заново отправляет все фоновые POST-запросы (около 5 штук) для загрузки дешёвых данных (календарь и т.д.).
Кэш не работает, приложение ведет себя так, будто `staleTime` равен 0.

## Ожидаемое поведение
Дешёвые фоновые запросы должны иметь адекватный `staleTime` (например, несколько минут). При быстром переходе туда-сюда данные должны браться из кэша (cache-hit), и новых запросов в Network быть не должно.

## Ссылки
- Найдено во время тестирования задачи: `test-DH-05` (Сценарий S10).

## Решение (2026-06-15)
Префетч отключён (`TASKS_PREFETCH_ENABLED = false`): при возврате на пикер фоновые
запросы не планируются и не повторяются — поведение «как будто staleTime=0» снято.
(QueryClient — стабильный браузерный синглтон, кэш при навигации не сбрасывается;
проблема была именно в повторном idle-префетче на маунте пикера.)
