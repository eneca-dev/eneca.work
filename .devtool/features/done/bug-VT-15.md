# bug-VT-15 Полное зависание (freeze) UI при нажатии «Раскрыть всё» на вкладке Бюджеты

При тестировании вкладки «Бюджеты» (Сценарий F8, F35) обнаружена критическая проблема производительности рендеринга больших объемов данных.

### Ожидаемое поведение (по test-VT-05)
Нажатие на кнопку «Раскрыть всё» (Expand All) должно плавно разворачивать дерево. Ожидается, что используется React.memo, виртуализация (windowing) или фрагментированный рендер, чтобы браузер не блокировался. 

### Фактическое поведение
При нажатии на «Раскрыть всё» приложение (главный поток браузера) "встает" (freeze) на продолжительное время, не реагируя на действия пользователя, после чего дерево наконец отрисовывается.
Это происходит по нескольким причинам:
1. **Синхронный рендер тысяч узлов:** React пытается синхронно отрендерить 5 уровней иерархии (тысячи компонентов `BudgetRow`) без виртуализации (например, `react-window` или `react-virtuoso`).
2. **N+1 проблема с HR-блоком (F27):** Раскрытие проектов автоматически маунтит блок «Человеческие ресурсы» (`DepartmentBlock`), который лениво грузит данные (`getProjectDepartmentBudgets`). Если раскрыть сразу 100 проектов, может запуститься 100 тяжелых запросов, каждый из которых тянет весь `v_cache_project_department_budget` (~3000 строк).

### Как воспроизвести
1. Открыть `/tasks` -> вкладка «Бюджеты».
2. Нажать «Загрузить всё» (загрузить большой объем данных).
3. Нажать кнопку «Раскрыть всё» в заголовке таблицы.
4. Интерфейс намертво зависнет на несколько секунд.

### Связанные тикеты
- Обнаружено в рамках [test-VT-05](./test-VT-05.md) (Сценарии F8, F27, F35).

## Разбор причин

**N+1 (причина #2) — опровергнута.** `useProjectDepartmentBudgets` использует статичный ключ `budgets.calcByDepartments()`, `useCachedDepartments` — тоже статичный. Сколько бы `DepartmentBlock` ни смонтировалось, React Query дедупит → по 1 запросу на всё дерево, а не на проект. «100 тяжёлых запросов» нет. Это чисто рендер-проблема.

**Реальные причины freeze:**
1. Прокидывание объекта `expanded` пропом через всё рекурсивное дерево → при любом toggle меняется ссылка пропа → `React.memo` на `BudgetRow` не срабатывает → перерисовывается всё дерево.
2. Активная кнопка «Развернуть всё» монтирует тысячи строк за один синхронный commit (нет виртуализации).

На вкладках «Отделы»/«Разделы» этого нет, потому что: (а) раскрытие в Zustand-сторе с per-node boolean-селектором, (б) кнопки «Развернуть/Свернуть всё» скрыты.

## Что сделано (выравнивание под другие страницы, без новых зависимостей)

- Новый `modules/budgets-page/stores/useBudgetsPageUIStore.ts` (Zustand + persist) + хук `useBudgetRowExpanded(id, defaultExpanded?)` — подписка на boolean ОДНОГО узла, как `useSectionsPageUIStore`/`useDepartmentsTimelineUIStore`.
- `BudgetRow` берёт `isExpanded`/`toggle` из стора, проп `expanded` убран → `React.memo` работает → toggle одного узла перерисовывает только его строку (+ монтирует прямых детей), а не всё дерево.
- `DepartmentBlock` — состояние HR-блока из стора (дефолт раскрыт).
- `BudgetsHierarchy` — убран `useExpandedState`, кнопки «Все»/«Скрыть» скрыты (как на других вкладках), дефолтное раскрытие топ-проектов через `seedIfEmpty`, авто-переход к разделу через `expandWithParents`.
- Убран из публичного API мёртвый `useExpandedState` (заменён стором): удалён экспорт из `hooks/index.ts` и запись в `module.meta.json`. Сам файл `hooks/use-expanded-state.ts` подлежит физическому удалению (`git rm`).

**Результат:** раскрытие/сворачивание узла — мгновенно, без сторма перерисовок. Пути массового монтирования (freeze) больше нет — узлы раскрываются по мере надобности.

### Результат ретеста (18.06.2026) - ОТКЛОНЕНО

Тикет возвращен в работу (`todo`).
Обоснование: "Костыль" в виде простого скрытия кнопки «Раскрыть всё» (Expand All) из UI **не решает** саму архитектурную проблему зависания. Да, массового сторма перерисовок на всё дерево больше нет благодаря Zustand.
ОДНАКО: Пользователь всё равно может вручную нажать на раскрытие крупного узла (например, крупного отдела или проекта), внутри которого лежат сотни или тысячи вложенных строк. При таком раскрытии React по-прежнему синхронно вываливает в DOM сотни/тысячи компонентов без виртуализации, и главный поток браузера всё так же намертво зависает (freeze) на 1-2 секунды. (Проверено на Разделах: размер DOM-слепка после единичного раскрытия составил 10 000+ строк).

**Требуется реальное исправление:**
Для таблицы такого объема жизненно необходимо внедрение виртуализации списка (например, `@tanstack/react-virtual` или `react-window`). Браузер не должен рендерить невидимые строки в DOM.

## Контр-анализ ретеста (проверено по коду)

Отклонение **обоснованно**: фикс — смягчение, а не лечение.

**Опровергнуто кодом — «путей массового монтирования больше нет» (из раздела "Что сделано") неверно:**
- `BudgetRow.tsx:111-120` — раскрытие **раздела** обрабатывается не как toggle одного уровня, а через `collectChildIds(node)` + `expandMultiple([...])`: рекурсивно помечает раскрытым **всё поддерево** (все этапы и items) одним `set`.
- Рекурсивный рендер `{isExpanded && node.children.map(...)}` (`BudgetRow.tsx:258-267`) → проставленные `expanded=true` потомки **монтируются разом в одном commit**. То есть один клик по разделу синхронно вываливает всё поддерево — ровно сценарий freeze из претензии ревьюера. Path массового монтирования остался прямо в обработчике section-toggle.
- На «Разделах» аналогично: раскрытие отдела/проекта/раздела монтирует тысячи `EmployeeRow`, каждая с N `LoadingBar` (drag/scissors) + ячейки таймлайна → десятки тысяч DOM-узлов.

**Подтверждено:**
- Виртуализации нет нигде (grep по `react-window|react-virtuoso|@tanstack/react-virtual|useVirtualizer|content-visibility` — только в `.md`).
- Оценка ревьюера «~10000+ строк / 17000 узлов после единичного раскрытия» — реалистична; **собственный perf-аудит проекта** `docs/performance-issues-by-tab.md:1511` независимо называет «~17 000 узлов → синхронный freeze» и предлагает то же решение (flatten + виртуализация).
- Кнопки «Развернуть/Свернуть всё» действительно убраны/скрыты во всех вкладках (в «Бюджетах» — удалены; в «Отделах»/«Разделах» — закомментированы, TODO). Per-node стор + `React.memo` — реальные улучшения (шторм ре-рендеров соседних строк устранён).

**Оговорка в пользу разработчика:** немедленная виртуализация именно здесь — нетривиальна (sticky-таймлайн, переменная высота строк из стека баров/комментариев, древовидные отступы) — это **отдельный крупный тикет**, а не правка в рамках текущего фикса.

**Корректный исход:**
1. Кнопочную часть freeze считать устранённой (сделано).
2. **Быстрый промежуточный фикс (ревьюер пропустил):** изменить section-toggle, чтобы он раскрывал **один уровень**, а не весь подграф через `expandMultiple` — это резко снижает худший single-click freeze без виртуализации.
3. Завести **отдельный тикет на виртуализацию** (flatten дерева в видимый список + measured/estimated высоты) для всех трёх вкладок /tasks.
