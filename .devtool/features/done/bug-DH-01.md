# bug-DH-01 Страница /tasks: не автозагружать вкладку — пикер вкладок + фоновый префетч

## Проблема
При открытии страницы «Задачи» (`/tasks`) приложение **сразу начинает грузить активную вкладку** (на скрине открыта вкладка «Бюджеты», блок «Человеческие ресурсы» всё ещё в статусе `загрузка...`). Пользователь ждёт тяжёлую загрузку, даже если ему нужна совсем другая вкладка.

![Страница /tasks: автозагрузка вкладки «Бюджеты»](./assets/bug-DH-01-tasks-tabs.png)

## Чего хотим
1. **Не автозагружать содержимое вкладки** при заходе на страницу.
2. Вместо контента показывать **пикер (выбор) из всех доступных пользователю вкладок** (на скрине: «Задачи», «Демопроект», «Бюджеты», «+»). Пользователь сам выбирает, что открыть.
3. Пока пользователь смотрит на пикер, **в фоне префетчить** данные доступных вкладок (background prefetch), чтобы при клике вкладка открывалась **быстрее** (в идеале — мгновенно из кеша).

## Идея реализации (черновик, уточнить при планировании)
- Дефолтное состояние страницы — экран выбора вкладки, без монтирования тяжёлого контента.
- Префетч через cache-модуль (`modules/cache`): `queryClient.prefetchQuery(...)` по ключам доступных вкладок, с приоритетом для часто используемых.
- Префетч должен быть **аккуратным**: не дублировать запросы, уважать `staleTime`, не блокировать UI пикера, отменяться при уходе со страницы.
- Не ломать deep-link: если на вкладку зашли по прямой ссылке (URL содержит конкретную вкладку) — открывать её сразу, как сейчас.

## Definition of Done
- [x] При заходе на `/tasks` без конкретной вкладки в URL показывается пикер, тяжёлый контент не монтируется.
- [x] В фоне идёт префетч данных доступных вкладок (видно в network/devtools, без дублей).
- [ ] Клик по вкладке открывает её ощутимо быстрее за счёт прогретого кеша.
- [ ] Deep-link на конкретную вкладку продолжает работать.
- [ ] Нет лишних/дублирующихся запросов и утечек подписок.

> Первые два пункта проверены вживую (Playwright + Network): на `/tasks` без `?tab` показан пикер, тяжёлый контент не смонтирован, в фоне идут POST `/tasks` (префетч). Полный прогон DoD (скорость клика, deep-link, отсутствие утечек) вынесен в тест-тикет **test-VT-05**.

## Решение
- **Источник истины рендера — URL `?tab=<id>`**, а не persisted `activeTabId`. Нет `?tab` → рендерится новый `TabPicker`, тяжёлые view-компоненты не монтируются; строка фильтра скрыта. Есть `?tab` → контент вкладки как раньше. `activeTabId` синхронизируется из URL (для «последней активной» и префетча).
- **Пикер** (`modules/tasks/components/TabPicker.tsx`): сетка карточек вкладок + «Новая вкладка» (через `TabModal`). Клик → `router.push('?tab=id')`; верхняя панель `TasksTabs` → `router.replace('?tab=id')`.
- **Сбалансированный префетч** (`modules/tasks/hooks/useTasksPrefetch.ts`): дешёвые общие запросы (`companyCalendar.events`, `departmentsTimeline.freshness`, `budgets.calc`) греются сразу в idle; тяжёлые — по hover карточки и один раз для последней активной вкладки. Вкладки без фильтров/«Загрузить всё» не префетчатся. Дедуп и `staleTime` — нативно через `prefetchQuery`/`prefetchInfiniteQuery`.
- **Deep-link**: `?tab=<id>` работает напрямую; легаси `?sectionId=...&highlight=true` (без `?tab`) открывает budgets.
- **Suspense**: `app/(dashboard)/tasks/page.tsx` обёрнут в `<Suspense>` (т.к. `TasksView`/`TasksTabs` читают `useSearchParams`).
- Изменённые файлы: `useTasksPrefetch.ts` (new), `TabPicker.tsx` (new), `TasksView.tsx`, `TasksTabs.tsx`, `page.tsx`, барели `hooks/index.ts` и `components/index.ts`.

## Для ревьюера (на что обратить внимание)
1. **Совпадение ключей префетча с live-хуками** — главное. Пустые фильтры: kanban использует `undefined`, departments/sections/budgets — `{}`. Если ключ префетча разойдётся с тем, что читает компонент, прогреется не тот кеш (тихий регресс). См. `prefetchHeavy` в `useTasksPrefetch.ts`.
2. **«Пустые» вкладки** (без фильтров и без «Загрузить всё») не должны слать тяжёлый запрос ни при hover, ни как last-active.
3. **Легаси deep-link budgets** (`?sectionId&highlight=true`) — проверить, что подсветка раздела всё ещё работает.
4. **Удаление активной вкладки** оставляет «висячий» `?tab` → показывается пикер (мягкий fallback, осознанное поведение, вне DoD).
5. `router.replace` в верхней панели vs `router.push` в пикере — поведение «назад» (из вкладки → пикер).
