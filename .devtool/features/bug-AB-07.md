# bug-AB-07 Цвет столбиков загрузки: плавная интерполяция вместо ступенчатых порогов

## Проблема
Цвет мини-баров X/Y задавался пятью жёсткими порогами, продублированными в двух файлах — `AggregatedBarsOverlay.tsx` (день) и `WeeklyAggregatedBarsOverlay.tsx` (неделя).

Пороги давали резкие скачки цвета между соседними процентами, а вся зона 70–94% красилась в жёлто-зелёный: нехватка 2 человек из 7 (71%) выглядела так же спокойно, как 90%. Дублирование требовало править оба файла синхронно.

## Решение
Единая функция `getBarStyle()` в новом `modules/sections-page/utils/bar-color.ts`, цвет — плавная HSL-интерполяция по опорным точкам.

Распределение ролей согласовано с постановщиком:
- **Недогруз** (X < Y, не хватает людей) — тревожная зона. 100% — зелёный, ~90% (6/7, 6/8) — оранжевый, далее плавно краснеет к 0% с ростом насыщенности.
- **Перегруз** (X > Y, людей больше плана) — нейтральный серо-голубой, без градации.

Изначально роли были распределены наоборот (жёсткий красный при >100%); поменяны местами после обсуждения — красный маркирует только реальную нехватку людей.

## Реализация
- `utils/bar-color.ts` (новый) — `getBarStyle()`; анкоры недогруза 0→hue 0, 50→20, 90→40, 100→142, alpha 0.75→0.5. Перегруз — константа `SURPLUS_STYLE`, экспорт `SURPLUS_ACCENT_COLOR` для линии отсечки.
- Оба overlay-компонента — локальные копии `getBarStyle` удалены, импортируется общая.
- Линия отсечки перегруза переведена с красного на `SURPLUS_ACCENT_COLOR`.

## На что обратить внимание
1. Проверить визуально на реальных данных: недогруз 50–90% (раньше жёлто-зелёная зона), перегруз, пустые ячейки.
2. Серо-голубой для перегруза — временное решение, оттенок может быть пересмотрен.
