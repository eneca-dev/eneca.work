# test-DH-05 Тест пикера вкладок и фонового префетча (/tasks)

Родительская задача: **bug-DH-01**. Тестируем по правилам из `bug-VT-02` («Человек + Нейросеть»).

## Цель
Проверить новое поведение страницы `/tasks`: при входе **без конкретной вкладки** показывается пикер, тяжёлый контент не монтируется и не грузится; в фоне идёт **сбалансированный префетч**; клик по вкладке открывает её ощутимо быстрее (кеш-хит); deep-link не сломан; нет дублей запросов и утечек подписок. Любые находки оформляем отдельными тикетами `bug-...` со ссылкой сюда.

## Контекст реализации (для проверяющего ИИ)
- Маршрут: `app/(dashboard)/tasks/page.tsx` (обёрнут в `<Suspense>`) → `TasksView` (`modules/tasks/components/TasksView.tsx`).
- **Источник истины активной вкладки — URL `?tab=<id>`** (не persisted `activeTabId`).
  - Нет `?tab` → рендерится `TabPicker` (`modules/tasks/components/TabPicker.tsx`), тяжёлые view-компоненты НЕ монтируются, строка фильтра скрыта.
  - Есть `?tab=<id>` → рендерится контент вкладки, как раньше.
  - Легаси deep-link `?sectionId=...&highlight=true` (без `?tab`) → открывает вкладку **budgets** (только она потребляет эти параметры).
- Навигация: клик по карточке пикера → `router.push('?tab=id')`; клик по вкладке в верхней панели → `router.replace('?tab=id')` (чтобы переключение между открытыми вкладками не засоряло историю). «Назад» из открытой вкладки → пикер.
- Префетч (`modules/tasks/hooks/useTasksPrefetch.ts`, включён пока показан пикер):
  - **A. Дешёвое общее, сразу в idle** (`requestIdleCallback`): `getCompanyCalendarEvents` (`companyCalendar.events()`, staleTime ∞), `getTeamsFreshness` (`departmentsTimeline.freshness()`, 5 мин), `getSectionCalcBudgets` (`budgets.calc()`, 3 мин).
  - **B. Тяжёлое, по hover/focus карточки** (`prefetchTab`) + **один раз для последней активной вкладки** (persisted `activeTabId`).
  - Ключи/параметры префетча СОВПАДАЮТ с live-хуками: kanban → `kanban.infinite(filtersApplied ? params : undefined)` (infinite, page 1, pageSize 15); departments → `departmentsTimeline.list(filtersApplied ? params : {})`; sections → `sectionsPage.list(... : {})`; budgets → `resourceGraph.list(... : {})`.
  - **Важно:** вкладка **без фильтров и без «Загрузить всё»** ничего не префетчит (live-компонент тоже ничего не грузит — `shouldFetch = filtersApplied || loadAllEnabled`).
  - Дедуп и проверку `staleTime` делает сам `prefetchQuery`/`prefetchInfiniteQuery` (no-op для свежих данных, join для in-flight). In-flight запросы намеренно не отменяются.
- Server Actions в App Router идут как **POST на `/tasks` с заголовком `Next-Action`** — различать по заголовку/телу ответа (все префетч-экшены POST-ят на `/tasks`, по URL не различить).
- Прочее на маунте `TasksView`: `reloadPermissions()` (useEffect) — возможный источник лишних POST `/tasks`.

## Среда
- `localhost:3000`, тестировщик авторизуется сам.
- Браузер открывает ИИ через Playwright MCP; тестировщик кликает в этом окне.
- ИИ читает console + network через Playwright, состояние БД — через Supabase MCP (только чтение).

## Сценарии (чек-лист)

### 🔴 Приоритет 1 — пикер и базовый префетч
- [ ] **S1. Холодный вход на `/tasks` без `?tab`.**
  - Ожидание: виден пикер («Выберите вкладку» + карточки всех вкладок + «Новая вкладка»); тяжёлого запроса активной вкладки (`getDepartmentsData`/`getResourceGraphData`/`getKanbanSectionsPaginated`/`getSectionsHierarchy`) на маунте **нет**; строка фильтра скрыта.
  - Искать: монтирование тяжёлого контента, ранний тяжёлый запрос, ошибки в console.
- [ ] **S2. Фоновый префетч на пикере.**
  - Ожидание: в фоне (idle) уходят дешёвые общие — `getCompanyCalendarEvents`, `getTeamsFreshness`, `getSectionCalcBudgets` — по 1 разу, плюс тяжёлый запрос **последней активной** вкладки (1 раз).
  - Искать: дубли одного ключа, шторм запросов, отсутствие префетча.
- [ ] **S3. Hover-префетч карточки.**
  - Навести на карточку вкладки (с фильтрами или «Загрузить всё») → ожидается префетч тяжёлого запроса именно этой вкладки. Навести на вкладку **без фильтров** → запроса быть НЕ должно.
  - Искать: лишние запросы для «пустых» вкладок, повторные запросы при многократном hover (должен быть кеш-хит/no-op).
- [ ] **S4. Клик по карточке → скорость открытия.**
  - Ожидание: URL получает `?tab=<id>`; контент открывается ощутимо быстрее (данные из прогретого кеша); для прогретой вкладки — мгновенно/без повторной тяжёлой загрузки.
  - Искать: повторный тяжёлый запрос вместо кеш-хита, рассинхрон ключа (прогрели один ключ — компонент читает другой).

### 🟡 Приоритет 2 — навигация и deep-link
- [ ] **S5. Deep-link по `?tab`.** Открыть `/tasks?tab=budgets` напрямую → сразу контент budgets, без пикера. Refresh остаётся на вкладке.
- [ ] **S6. Легаси deep-link.** Открыть `/tasks?sectionId=<id>&highlight=true` (без `?tab`) и `/tasks?tab=budgets&sectionId=<id>&highlight=true` → открывается budgets, нужный раздел подсвечен/раскрыт.
- [ ] **S7. Кнопка «Назад».** Пикер → выбрать вкладку → «назад» возвращает к пикеру.
- [ ] **S8. Переключение вкладок в верхней панели.** Открытая вкладка → клик по другой вкладке в баре → контент меняется, URL `?tab` обновляется; быстрый перебор A→B→A не плодит записи истории (используется `router.replace`).

### 🟢 Приоритет 3 — фон, подписки, устаревание
- [ ] **S9. Подписки Realtime на пикере.** Ожидание: на пикере НЕ поднимаются подписки тяжёлых модулей (они монтируются только при открытии вкладки). Проверить отсутствие утечек при многократном входе/выходе на `/tasks`.
- [ ] **S10. Уважение `staleTime`.** Повторный вход на пикер вскоре после первого → свежие данные не перезапрашиваются (no-op); протухший kanban (>2 мин) при hover — повторно прогревается.
- [ ] **S11. Уход со страницы во время префетча.** Уйти с `/tasks` пока идёт idle-префетч → новые префетчи не планируются (нет «хвоста» запросов после ухода).

## Найденные баги
_(ИИ дозаполняет по ходу; на каждый подтверждённый баг — отдельный тикет `bug-...` со ссылкой сюда)_
- Шторм запросов на маунте пикера (S1/S2): отправляется около 15 POST-запросов к `/tasks`. Ожидалось около 4 запросов. Возможно, проблема в `reloadPermissions` или `useTasksPrefetch` без правильного `staleTime`/дедупликации.
- Повторный тяжёлый запрос (кэш-мисс) при клике по вкладке (S4): UI рендерится быстро, но в Network уходит повторный POST-запрос с данными вкладки. Вероятно, рассинхрон ключей префетча и хука (prefetchQuery vs useQuery).
- Deep-link не работает (S5): При переходе по прямой ссылке `?tab=budgets` вместо самой вкладки всё равно открывается пикер. Обновление страницы (F5) также оставляет пользователя на пикере.
- Ошибка RealtimeSync в консоли (S5): `CHANNEL_ERROR Error: mismatch between server and client bindings for postgres changes`.
- Легаси deep-link не работает (S6): При переходе по ссылке `?sectionId=123&highlight=true` вкладка бюджетов не открывается автоматически, остаётся пикер.
- Утечка подписок Realtime (S9): Тяжёлые WebSocket-подписки открываются сразу при загрузке пикера (до перехода во вкладку) и не закрываются при выходе обратно на пикер. Подписка, видимо, висит на глобальном layout, а не на компоненте вкладки.
- Игнорирование staleTime (S10): При уходе с пикера на другую страницу и быстром возврате обратно, приложение не использует свежий кэш, а заново делает все фоновые POST-запросы.
- Отсутствие отмены запросов (AbortSignal) (S11): При быстром уходе с пикера фоновые запросы продолжают выполняться (не получают статус `canceled`), возвращая `200 OK` вхолостую.

## Результаты
**Итог тестирования:** 
Основной функционал префетча по наведению мыши и оптимистичный UI работают (вкладки открываются быстро). Однако логика работы с кэшем, сетью и подписками реализована со значительными архитектурными ошибками, что приводит к перегрузке сервера, утечкам памяти и трафика.

**Заведённые баги:**
1. `bug-DH-06`: Шторм запросов на маунте пикера. — ✅ закрыт (в `done/`)
2. `bug-DH-07`: Повторный запрос (кэш-мисс) при клике по вкладке. — ✅ закрыт (в `done/`)
3. `bug-DH-08`: Не работают прямые ссылки (deep-links) `?tab=`. — 🟠 ОТКРЫТ
4. `bug-DH-09`: Ошибка `CHANNEL_ERROR` от RealtimeSync. — ✅ закрыт (в `done/`)
5. `bug-DH-10`: Утечка подписок Realtime (WebSocket) на пикере. — 🟠 ОТКРЫТ (частично)
6. `bug-DH-11`: Игнорирование `staleTime` при возврате на пикер. — ✅ закрыт (в `done/`)
7. `bug-DH-12`: Утечка сетевых запросов (нет `AbortSignal`) при уходе со страницы. — ✅ закрыт (в `done/`)

**Предложения по исправлению:**
Требуется комплексный рефакторинг хука `useTasksPrefetch` и логики монтирования/маршрутизации (Layout/Page). Необходимо внедрить дедупликацию, проверить ключи кэширования `QueryClient`, внедрить `AbortController`, а также перенести инициализацию `RealtimeSync` внутрь компонентов самих вкладок.

## Обновление 2026-06-15: бóльшая часть багов неактуальна

Вместо полного рефакторинга применён **мягкий фикс источника проблем** (2 файла):

1. **Фоновый префетч `/tasks` отключён** флагом `TASKS_PREFETCH_ENABLED = false`
   (`modules/tasks/components/TabPicker.tsx`). Пикер вкладок и навигация работают
   как прежде; данные грузятся при открытии вкладки. → снимает причину **DH-06,
   DH-07, DH-11, DH-12** (все они — артефакты префетча).
2. **Убран дубль `<RealtimeSync/>`** (`app/ClientProviders.tsx` → `<QueryProvider
   disableRealtime>`): был второй инстанс на том же канале `'cache-sync'`. → снимает
   **DH-09** (`CHANNEL_ERROR`). Этот баг был пре-существующим, не из `bug-DH-01`.

Сборка `npm run build` проходит. **DH-06/07/09/11/12 перенесены в `done/`** и больше
не актуальны при выключенном префетче.

### Осталось открытым (этим фиксом НЕ закрыто)

  маршрутизации/чтению `searchParams` пикера, не к префетчу. Требует отдельного фикса.
- **DH-10** (подписки Realtime не tab-scoped): дубль убран, но архитектура realtime

  подписки только внутри открытой вкладки — не выполнена.
