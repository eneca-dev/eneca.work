# bug-VT-16 Некорректная работа Realtime-обновлений на вкладке «Бюджеты»

При тестировании вкладки «Бюджеты» (Сценарии F32, F33) выявлено, что обновления в реальном времени не доставляются или отрабатывают некорректно.

### Ожидаемое поведение (по test-VT-05)

Изменение бюджета в соседней вкладке или другим пользователем должно приводить к получению websocket-события из Supabase, инвалидации ключей `budgets.all` / `resourceGraph.all` и бесшовному обновлению цифр в UI без перезагрузки страницы (F5).

### Фактическое поведение

Realtime-обновления для бюджетов не применяются корректно в браузере. Это может быть связано с:

1. Отсутствием/ошибкой подписки на таблицу `budgets` в `modules/cache/realtime/config.ts`.
2. Неправильной инвалидацией ключей `queryClient.invalidateQueries(...)` внутри обработчика realtime-событий.
3. Потерей сессии (аналогично ложной тревоге с `No session`, но здесь это влияет на получение payloads).

### Как воспроизвести

1. Открыть `/tasks` -&gt; вкладка «Бюджеты» в двух разных окнах/устройствах.
2. В одном окне изменить значение `Выделенного` бюджета у любого раздела.
3. Во втором окне значение не обновляется автоматически.

### Связанные тикеты

- Обнаружено в рамках [test-VT-05](./test-VT-05.md) (Сценарии F32, F33).

## Разбор причины

Гипотезы тикета **не подтвердились**:

- Подписка на `budgets` есть — `modules/cache/realtime/config.ts` (`budgets → budgets.all`).
- Таблица `budgets` в публикации `supabase_realtime`, replica identity = PK → UPDATE-события доставляются.
- Ключи совпадают по префиксу: `budgets.all` (`['budgets']`) матчит `budgets.list({...})` страницы. Optimistic-апдейт идёт через `setQueriesData` (префикс-матч) → своё окно обновляется мгновенно.

**Реальная причина была:** `<RealtimeSync />` рендерился дважды (в `QueryProvider` и в `ClientProviders`) → два инстанса на одном канале `cache-sync`. Устранено в [bug-SB-02](./bug-SB-02.md).

## Итог тестирования

Перепроверено вживую (две вкладки, dev перезапущен): **realtime бюджетов работает** — `Subscription status: SUBSCRIBED`, событие `UPDATE on budgets` доходит, правка суммы в одной вкладке прилетает в другую. Исходная формулировка «не доставляется» **не подтвердилась**.

**НО обновление происходит очень долго.** Причина — слишком широкие realtime-инвалидации (`*.all` на каждое изменение любой таблицы): при активной работе команды каждый клиент штормит рефетчами тяжёлых выборок. То есть события доставляются корректно, но реакция UI медленная.
