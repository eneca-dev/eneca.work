# feature-AB-05 Группировка и сортировка проектов на странице «Разделы»

## Проблема
После feature-AB-04 (недельный вид) на странице «Разделы» проявились смежные проблемы:
1. Список проектов внутри отдела не отражал, что реально в работе — давно закрытые проекты (нет активности 3+ мес.) мешались среди актуальных, а сортировки по актуальности не было вообще.
2. Служебные "проекты"-корзины (Отпуск, Прочие работы, Непроектные загрузки) могли попадать в топ списка, если у них загрузка идёт прямо сейчас.
3. В недельном режиме шапка не показывала месяцы (только недели) — терялась ориентация по календарю.
4. Ёмкость проекта иногда отображалась как `0.6000000000000001` вместо `0.6` (сумма чисел с плавающей точкой без округления).
5. Обнаружился React-ключ-баг: один и тот же проект может легитимно входить сразу в два отдела (ответственного + сотрудника) — без учёта deptId в key это давало ~60 ошибок "duplicate key" в консоли.
6. Всплывающий календарь выбора периода использовал зашитые slate/blue-цвета вместо палитры темы.

## Решения (согласованы с постановщиком)
1. Проекты без активности 3+ месяца и без планов вперёд — сворачиваются в отдельную коллапс-группу «Завершённые» внизу списка отдела (не удаляются, не блокируются — просто не мешают).
2. Формула активности — только по датам loadings/sections (`loading_start/finish`, `section_end_date`, `section_created`); `project_status` в БД сознательно не используется — признан неактуальным/ненадёжным после ручного анализа данных.
3. Сортировка проектов внутри отдела — по актуальности загрузок: идёт сейчас → скоро начнётся → недавно закончилась → нет загрузок вообще → служебные "проекты"-корзины (всегда в самом низу, независимо от их текущей загрузки).
4. Добавлена возможность выбрать период в календаре — тогда критерий свёрнутой группы меняется с «Завершённые» (от сегодня) на «Нет загрузок за период» (нет загрузок и нет введённой ёмкости `capacityOverrides` внутри выбранного диапазона). Сортировка при этом не меняется — совмещается с п.3. Раздели (Object/Section) эта логика не затрагивает — только уровень проектов.
5. Недельный вид — добавлена строка месяцев в шапке (по образцу дневного режима), чередование фона теперь по месяцам, а не по неделям (как и в ячейках таймлайна).

## Как решено
- `modules/sections-page/actions/index.ts` — при построении иерархии трекается активность каждого проекта (`hasActiveLoadingNow`/`nearestFutureLoadingStart`/`mostRecentPastLoadingFinish`/`isStale`), считается один раз за проход по строкам.
- `modules/sections-page/utils/sort-projects.ts` — `compareProjectsByActuality()` (4 уровня приоритета, служебные проекты — отдельным нижним уровнем по точному совпадению имени, без учёта регистра/пробелов).
- `modules/sections-page/utils/period-activity.ts` (новый) — `hasActivityInPeriod()`, чистая клиентская функция по уже загруженным loadings/capacityOverrides, без похода в БД.
- `modules/sections-page/components/flatten-sections.ts` — критерий и подпись свёрнутой группы («Завершённые» / «Нет загрузок за период») параметризованы, зависят от того, задан ли период в календаре.
- `modules/sections-page/components/rows/StaleGroupRow.tsx` (новый, вынесен из инлайна) — принимает label/title снаружи.
- React-key фикс — ключи `proj:`/`os:`/`emp:` в `flatten-sections.ts` включают `deptId`, чтобы не схлопывались при легитимном дублировании проекта в двух отделах.
- Округление ёмкости — `Math.round(sum * 100) / 100` в местах агрегации (`ProjectRow.tsx`, `DepartmentRow.tsx`), было пропущено при суммировании чисел с плавающей точкой.
- `modules/resource-graph/utils/weekly-cell-utils.ts` + `components/shared/timeline/WeeklyHeader.tsx` — месяцы в шапке недельного режима, по прямой аналогии с дневным (`monthIndex` на `WeekCell`).
- Цвета попапа календаря (`components/ui/date-picker/DatePicker.tsx`, `TimelineDatePopover.tsx`) — зашитые `slate-*`/`gray-*` заменены на токены темы (`bg-popover`, `border-border`).
- Также правки из code-review прохода: единообразный ключ трекера активности (строка `deptId:projectId`, как у соседних Map), именованные хелперы вместо голых `as unknown as` каста в `hooks/index.ts`, уточняющие комментарии.

## На что обратить внимание ревьюеру
1. Вручную проверить отдел с проектами, дублирующимися между отделом ответственного и отделом сотрудника (пример был найден в БД: `13d8712c-969c-40e4-a911-afbe10eaee40`) — консоль не должна давать "duplicate key" при полном разворачивании дерева.
2. Проверить переключение периода в календаре — группа должна на лету менять подпись/состав («Завершённые» ⇄ «Нет загрузок за период»), без перезапроса к серверу.
3. Формула `isStale` (3 месяца) — намеренно не обсуждали её сокращение до 1 месяца: по данным `КР гражд` проект «Депо 12-я очередь» (реально в работе) и несколько "мусорных" проектов оказываются в одном и том же диапазоне 40-60 дней простоя — короткий порог задел бы и настоящие проекты. Если требование изменится — искать другой признак (например, наличие реальных loadings, а не плановой `section_end_date`), не просто сокращать порог.
4. `npm run build` не запускала (см. правило проекта) — не самая маленькая пачка правок, стоит прогнать перед мержем.
